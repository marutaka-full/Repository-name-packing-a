# 技能実習／育成就労 法令監視システム

法令・告示・通知の改正を日次で追跡し、変更を検知して監査証跡を残す。

出典: e-Gov法令API（デジタル庁）／政府標準利用規約 第2.0版

---

## 導入手順（テスト機・事業所PC共通）

### 1. ダウンロード

このページ上部の緑の **Code** ボタン → **Download ZIP**。git は不要、ブラウザだけでよい。

zip を右クリック → すべて展開。できたフォルダの**中身**を `C:\法令監視\` へ置く。

### 2. 動作確認

`0_セットアップ確認.bat` をダブルクリック。以下が全部出れば合格。

```
Python 3.x.x
  結果: 10/10 PASS
  結果: 9/9 PASS
  結果: 7/7 PASS
  接続OK  HTTP 200
```

Python が無ければ python.org から導入する。
インストーラの **「Add python.exe to PATH」に必ずチェック**を入れること。

### 3. 実行

`条文を更新する.bat` をダブルクリック。**2回続けて**実行する。

- 1回目 … 土台づくり。`変更 0条` が正常
- 2回目 … `変更 0条` のままなら誤検知なしで正常

詳細は [docs/導入手順書_テストPC.md](docs/導入手順書_テストPC.md) を参照。

## 毎日の運用で見る場所

実行後、この行だけ確認する。

```
条文同期 完了: 変更 0条 / 0法令（取得成功 12/12件）
                                        ~~~~~
```

**`12/12` なら、その日の確認は完了。** それ以外なら未確認。ネットワークを直して再実行する。

`変更 0条` だけを見て安心しないこと。改正がなかった日も、通信が切れていた日も、同じく `0条` と出る。

取得に失敗した場合は警告ブロックと失敗した法令名が表示され、終了コード **3** で終わる。
自動実行を組む際はこれを拾うとよい。

| 終了コード | 意味 |
|---|---|
| 0 | 正常。全件確認できた |
| 3 | 取得失敗あり。**未確認**。要再実行 |
| 9 | Python が見つからない（bat判定） |

## ファイル構成

| ファイル | 役割 |
|---|---|
| `law_text_sync.py` | 条文の保管・更新・差分検知（日常運用の中核） |
| `monitor_layer1.py` | 層1: 法律・政令・省令の改正監視 |
| `monitor_layer235.py` | 層0/2/3: パブコメ予兆・告示・通知の監視 |
| `run_scheduler.py` | 統合スケジューラ（daily / weekly） |
| `config_laws.json` | 監視対象の法令14件 |
| `config_sources.json` | 層0/2/3の監視先URL |
| `条文を更新する.bat` | 日次実行用。`law_text_sync.py` を叩く |
| `0_セットアップ確認.bat` | 導入時の確認用。自己検証＋疎通 |

依存ライブラリなし。Python 3.8以上の標準ライブラリのみで動く。

### git で共有しないもの（`.gitignore` 済）

`change_log.jsonl`・`texts/`・`snapshots/` は各PCで実行時に生成される実データ。
特に `change_log.jsonl` は監査証跡なので、git 経由で上書きし合うと壊れる。

## 設計上の判断

- **官報（kanpo.go.jp）は自動取得しない。** 官報発行サイトの利用ルールでクローラによる
  データ収集が明示的に禁止されているため、確認用リンクに留めている
- **初回は基準作成のみ**（変更0件）。2回目以降に差分を検知する
- 取りこぼし防止を優先し、daily/weekly とも全件チェックする
